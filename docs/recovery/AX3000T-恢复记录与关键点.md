# 小米 AX3000T（RD03）修复记录与恢复关键点

> 更新时间：2026-09-19  
> 设备：小米 AX3000T，型号 RD03，MT7981B，stock bootloader 分区布局  
> 用途：记录已经验证过的修复思路，并防止把不同故障的处理方式混用。

## 1. 先看结论

这台路由器遇到过两种性质完全不同的启动故障：

1. **错误的外部内核模块被开机自动加载**：系统固件本体仍然完整，可以从恢复系统进入原 overlay，删掉错误模块和启动项后恢复。
2. **当前故障：UBI 中的 `kernel` 卷为空或不可用**：U-Boot 读出的 kernel 长度是 `0x0`，没有可启动内核。此时删 overlay、按 Reset、恢复出厂设置都无效，必须使用 TTL 进入 U-Boot，通过 TFTP 启动/写入恢复镜像，再用 `sysupgrade -n` 安装正式固件。

最重要的判断规则：

| 串口现象 | 故障层级 | 正确处理 |
|---|---|---|
| 内核已经启动，随后在加载 `.ko`、UU 或防火墙模块时 panic | overlay/模块问题 | 从恢复系统挂载原 overlay，删除错误模块和自动加载项 |
| `Reading from volume 'kernel' ... size 0x0`，随后 `Wrong Image Format` | 固件/UBI kernel 卷问题 | U-Boot 菜单 4 + TFTP 恢复，然后 `sysupgrade -n` |
| U-Boot 菜单都不出现，BL2/FIP 阶段报错 | 引导链问题 | 本文方案不适用；不要自行刷菜单 5/6 |

## 2. 当前故障的实锤

TTL 串口已经重复捕获到：

```text
Boot failure detected on both systems
ubi0: attached mtd9 (name "ubi", size 34 MiB)
Reading from volume 'kernel' to 0x46000000, size 0x0 ... OK
Wrong Image Format for bootm command
ERROR: can't get kernel image!
resetting ...
```

含义如下：

- BL2、FIP、NAND 和 U-Boot 都仍能工作。
- U-Boot 能进入启动菜单，也能初始化 `eth0`。
- 失败点是 UBI 的 `kernel` 卷：读到的镜像长度为零，`bootm` 没有合法内核可启动。
- 约 2～3 秒一次的网线断开/重连，是重启循环中交换芯片和 PHY 被反复初始化造成的，不代表网线一定没插好。
- Reset 只能处理 overlay/配置，不能凭空重建缺失的 kernel，因此当前不要再反复按 Reset。

## 3. 之前成功修复“错误 kmod”事故的方法

### 3.1 当时的根因

当时手工复制了与正在运行内核 ABI 不匹配的外部 `.ko`，并加入 `/etc/modules.d/` 自动加载。开机加载后触发内核 panic，形成重启循环。

涉及的错误项包括：

```text
/etc/modules.d/nf-ipt
/etc/modules.d/ipt-core
/etc/modules.d/nft-compat
/lib/modules/6.6.144/x_tables.ko
/lib/modules/6.6.144/ip_tables.ko
/lib/modules/6.6.144/nft_compat.ko
/lib/modules/6.6.144/ipt_*.ko
/lib/modules/6.6.144/iptable_*.ko
/lib/modules/6.6.144/xt_*.ko
```

### 3.2 当时为什么能修

那次固件中的 kernel 和 rootfs 仍然存在，只是 overlay 里的错误文件在启动过程中把系统搞崩。因此先从内存恢复镜像启动一个干净系统，再挂载原来的 overlay，就能在不依赖原系统完整启动的情况下清理错误文件。

### 3.3 当时的处理顺序

1. TTL 观察启动日志，确认 U-Boot、kernel 和 rootfs 本身能读出，崩溃发生在模块加载阶段。
2. 从恢复镜像进入临时系统。
3. 停止或禁用 UU 启动项，避免它继续调用缺失/错误的 netfilter 模块。
4. 挂载原 overlay，先确认目标路径，再删除上述 `/etc/modules.d/` 自动加载项和手工复制的 `.ko`。
5. 重启并持续观察串口，确认不再 panic。

如果以后再次遇到同类事故，挂载点可能表现为 `/mnt/overlay/etc/...`，也可能位于 `/mnt/overlay/upper/etc/...`。必须先用以下命令定位，不能猜路径直接删除：

```sh
find /mnt/overlay -type f \( -path '*/etc/modules.d/*' -o -path '*/lib/modules/*/*.ko' \) | sort
find /mnt/overlay -type l -path '*/etc/rc.d/*' -ls
```

确认后应先打包备份或移动到隔离目录，再清理。**这套办法只适用于内核已经存在、故障来自 overlay 自动加载内容的情况；不适用于当前 `kernel size 0x0`。**

## 4. 当前应使用的完整恢复流程

### 4.1 所需连接

- USB-TTL：当前识别为 `COM5`，参数 `115200 8N1`。
- TTL 只连接 `GND / TX / RX`，**不要连接 3.3V 或 5V 电源线**。
- TX 与 RX 交叉连接，共地。
- 电脑使用有线网卡直连路由器。U-Boot 阶段没有 Wi-Fi。
- 电脑有线网卡临时设置为 `192.168.10.100/24`，不填网关和 DNS。

### 4.2 TFTP 文件与服务器

U-Boot 的已知网络参数：

```text
路由器 U-Boot IP: 192.168.10.1
TFTP 服务器 IP:   192.168.10.100
掩码:             255.255.255.0
请求文件名:       firmware_ubi.bin
```

之前自写 PowerShell TFTP 服务遇到过两个兼容问题：

- timeout OACK 协商不兼容；
- 第 256 个数据块附近出现重复 ACK。

因此实际恢复优先使用已经准备好的 **Tftpd64 v4.70**：

```text
C:\Users\<user>\Documents\Codex\2026-09-14\i\work\Tftpd64_v4.70\tftpd64.exe
```

Tftpd64 的根目录应选择：

```text
C:\Users\<user>\Documents\Codex\2026-09-14\i\latest-handoff-20260919\ax3000t-recovery-handoff\recovery
```

服务器接口选择 `192.168.10.100`。若 Windows 防火墙弹窗，应允许专用网络上的 TFTP/UDP；恢复完成后可以删除临时规则和临时 IP。

### 4.3 进入 U-Boot 升级菜单

1. 先启动 Tftpd64，并确认根目录下存在 `firmware_ubi.bin`。
2. 打开 COM5 串口，确认参数为 `115200 8N1`。
3. 路由器断电再通电。
4. 看到以下倒计时后立即发送一次按键，打断自动启动：

```text
Hit any key to stop autoboot
```

5. 在菜单中选择：

```text
4. Upgrade firmware
```

可以用方向键选中第 4 项再回车；若串口软件按键映射可靠，也可发送一次 `4` 和 Enter。不要连续发送，避免字符落入后面的输入框。

### 4.4 升级菜单的正确输入

按提示逐项输入：

```text
Run image after upgrading? (Y/n): Y

Available load methods:
0 - TFTP client (Default)
Select (enter for default):       # 直接按 Enter

Input U-Boot's IP address: 192.168.10.1
Input TFTP server's IP address: 192.168.10.100
Input IP netmask: 255.255.255.0
Input file name: firmware_ubi.bin
```

关键操作：

- 每个提示只输入一个值并等待下一条提示出现。
- 如果一行已经出现旧字符或输错，用 `Ctrl+U` 清空整行，再输入正确值。
- 不要像之前那样直接在错误值后继续输入，否则会得到类似 `192.168.10.1002` 或 `255.255.255.0192...` 的拼接值。
- 看到 `flags type check failure` 时说明当前字段被污染，应清空该行重输，不要继续下一项。
- **绝对不要选择菜单 5（Upgrade ATF BL2）或菜单 6（Upgrade ATF FIP）**。这两项会触碰引导链，风险远高于当前恢复所需。

### 4.5 判断 TFTP 是否成功

成功时 Tftpd64 应看到对 `firmware_ubi.bin` 的读取请求和持续传输，串口应出现加载进度，随后进入恢复系统，而不是再次显示 `kernel size 0x0`。

若没有 TFTP 请求：

1. 检查电脑有线 IP 是否确实为 `192.168.10.100/24`。
2. 检查 Tftpd64 绑定的 Server interface 是否为 `192.168.10.100`。
3. 临时关闭其他网卡对该网段的干扰，但不要卸载驱动。
4. 更换 AX3000T 的物理网口逐个测试；U-Boot 可能只初始化其中一个口。
5. 注意循环重启时 Windows 可能暂时显示 `Disconnected`，应以 U-Boot 停在升级菜单后的链路状态为准。

### 4.6 恢复系统启动后的正式刷写

恢复镜像进入内存系统后，管理地址可能为 `192.168.100.1` 或 `192.168.1.1`。确认能够 ping/SSH 后，将正式镜像复制到 `/tmp`。

优先尝试新镜像：

```sh
scp new-sysupgrade.bin root@<路由器IP>:/tmp/
ssh root@<路由器IP> "sha256sum /tmp/new-sysupgrade.bin"
ssh root@<路由器IP> "sysupgrade -n /tmp/new-sysupgrade.bin"
```

其中 `-n` 是关键：**不保留旧 `/etc` 配置**。之前保留旧配置后，旧 OpenClash、UU 启动项和新系统文件叠加，是启动异常的重要风险源。

如果新镜像仍无法启动，退回已知可启动镜像：

```sh
scp known-good-sysupgrade.bin root@<路由器IP>:/tmp/
ssh root@<路由器IP> "sha256sum /tmp/known-good-sysupgrade.bin"
ssh root@<路由器IP> "sysupgrade -n /tmp/known-good-sysupgrade.bin"
```

刷写过程中不要断电。重启后先确认系统、LAN、Wi-Fi 和 SSH 稳定，再安装插件或恢复配置。

## 5. 配置恢复原则

配置备份只用于提取需要的内容，不能整体覆盖新系统的 `/etc`。

推荐顺序：

1. 首次以全新配置启动并观察稳定性。
2. 手工恢复 LAN/WAN 的必要设置。
3. 手工恢复 SSID、密码和无线参数。
4. 安装与当前固件/内核匹配的 OpenClash、UU 等软件。
5. 最后选择性导入 OpenClash 配置、订阅信息和 UU 身份文件。
6. 每完成一层就重启验证，便于定位哪一层引入问题。

不要做以下操作：

- 不要把旧备份的整个 `/etc` 覆盖到新系统。
- 不要手工复制其他构建产生的 `.ko`。
- 不要使用 `opkg --force-depends` 强装内核模块。
- 不要恢复旧的 `/etc/modules.d/` 和 `/etc/rc.d/` 链接。
- 不要在基础系统尚未稳定时同时安装 OpenClash、UU 和多套 DNS/广告过滤组件。

## 6. 为什么内核模块必须来自同一次构建

OpenWrt/iStoreOS 的 kmod 不只要求内核版本号相同，还必须匹配该次构建的内核配置和 ABI/hash。即使两边都显示 `6.6.144`，不同构建生成的模块也可能不兼容。

错误模块的典型后果不是“插件打不开”，而是模块加载时直接 kernel panic，造成整机循环重启。因此：

- 需要 `kmod-nft-compat`、`kmod-nf-ipt` 等功能时，应把它们加入同一次固件构建。
- 不能从公网源、另一台设备或另一份固件中抽取 `.ko` 强行放进 `/lib/modules/`。
- 包管理器报告依赖不匹配时，应停止并重新构建固件，不能用 `--force-depends` 绕过。

## 8. 最短恢复清单

如果只看这一节，严格按顺序执行：

1. COM5，`115200 8N1`，TTL 仅接 GND/TX/RX。
2. 电脑有线 IP 设为 `192.168.10.100/24`。
3. 启动 Tftpd64，目录指向 `recovery`，接口选 `192.168.10.100`。
4. 路由器上电，在 `Hit any key to stop autoboot` 时打断。
5. 选择 `4. Upgrade firmware`。
6. 依次输入 `Y`、Enter、`192.168.10.1`、`192.168.10.100`、`255.255.255.0`、`firmware_ubi.bin`。
7. 恢复系统启动后核验镜像 SHA-256。
8. 执行 `sysupgrade -n /tmp/new-sysupgrade.bin`。
9. 若失败，改刷 `known-good-sysupgrade.bin`，仍必须使用 `-n`。
10. 系统稳定后只选择性恢复配置，不整体覆盖 `/etc`，不手工复制任何 `.ko`。

## 9. 一句话经验

**先通过串口确定故障发生在 U-Boot、kernel 还是 overlay，再选择修复层级；看到 `kernel size 0x0` 就直接走 U-Boot/TFTP，不再用 Reset 或删配置碰运气。**
